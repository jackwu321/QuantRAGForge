# v0.4.0 — finish kb_root migration + close the query-feedback loop

## Context

v0.3.0 unified 9 subcommands under `qlw` and made every write path **resolve `kb_root` at handler time** (not at module import time), fixing the `pipx`-broken `ROOT = Path(__file__).resolve().parent`. v0.3.0 was a fix-on-top, so it left three loose ends:

1. **`shared.py` still defines module-level path constants** (`WIKI_DIR`, `WIKI_CONCEPTS_DIR`, `WIKI_SOURCES_DIR`, `WIKI_INDEX_PATH`, `WIKI_STATE_PATH`, `WIKI_LINT_PATH`, `REJECTED_SOURCES_PATH`). They're a trap — any new code that touches them will silently write into the pipx venv. Most are now dead, but the existence of `ROOT` + those names invites regressions.
2. **CLI handlers still pass `argparse.Namespace` objects between modules.** Three sites construct a fake Namespace to fake the argparse contract: `ingest/source.py:309-328` (calls `wiki.compile._run` and `embed._run`), `ingest/source.py:40-49` (`_dispatch_wechat` calls `ingest.wechat.ingest_single_url`), and `agent/tools.py:181-189` (calls `enrich.run_enrich_batch` helpers). On top of that, `agent/tools.py` `ingest_articles` (`:122-141`) calls `dispatch_url(...)` without threading `kb_root`, so the downstream code falls back to `resolve_kb_root(None)` (cwd/env) and silently writes to the wrong place when the agent isn't run from the user's KB dir.
3. **The query-feedback loop is wired but not closed.** `quant_llm_wiki/wiki/maintain.py` already provides `append_query_log()` writing to `<kb_root>/wiki/queries/`, and `qlw lint --maintain` already calls `run_maintenance()` which consumes those logs. But `qlw ask` / `qlw brainstorm` never actually call `append_query_log()` — so today the queries folder stays empty and `--maintain` has nothing to chew on.

v0.4.0 finishes all three.

## Workstream A — Delete module-level path state from `shared.py`

**Goal**: After v0.4.0, `shared.py` exports zero `Path` constants that close over `ROOT`. Everything that needs a path takes it as an argument from the caller.

### A1. Delete dead constants (6 of 7)

These have **no production callers** — only `tests/test_wiki_paths.py` and dependent `shared.py` definitions reference them. `compile.py`, `lint.py`, `agent/tools.py` already compute the equivalent paths dynamically from `kb_root`.

Remove from `quant_llm_wiki/shared.py`:
- `ROOT = Path(__file__).resolve().parent` (line 23) — keep ONLY the `load_dotenv(ROOT / ".env")` call by inlining; do not export `ROOT`.
- `WIKI_DIR`, `WIKI_CONCEPTS_DIR`, `WIKI_SOURCES_DIR`, `WIKI_INDEX_PATH`, `WIKI_STATE_PATH`, `WIKI_LINT_PATH` (lines 42–47).
- The big "WARNING" comment block (lines 29–41) — no longer needed.

Delete `tests/test_wiki_paths.py` (its sole job was asserting these constants exist; replace with a 3-line test in `tests/test_kb_root_resolution.py` asserting that `resolve_kb_root` is the only source of truth, if anything is needed at all).

### A2. Convert `REJECTED_SOURCES_PATH` to a parameterized helper

`REJECTED_SOURCES_PATH = ROOT / "rejected_sources.json"` (`shared.py:85`) is closed over by 4 helpers (`load_rejected_sources`, `save_rejected_sources`, `find_rejected_source`, `add_rejected_source`). Both production callers are in `agent/tools.py` and run at handler time with `kb_root` already resolved.

**Change**: drop the module-level constant. Each of the 4 helpers takes `rejected_sources_path: Path` as its first argument. Update the 2 callers:
- `agent/tools.py:123` (`ingest_article` → `find_rejected_source(...)`)
- `agent/tools.py:352` (`set_article_status` → `add_rejected_source(...)`)

Both already have `kb_root = resolve_kb_root(None)` in scope; just thread `kb_root / "rejected_sources.json"`.

### A3. `.env` loading stays

`load_dotenv(Path(__file__).resolve().parent / ".env")` at import time is fine — it's a no-op when the venv has no `.env`, and is the documented way to seed `LLM_API_KEY` in dev. Inline the path; don't keep a `ROOT` global.

## Workstream B — Typed business functions; CLI handlers are thin parsers

**Goal**: Every cross-module call uses a typed signature (`kb_root: Path` + named kwargs). No `argparse.Namespace` / `types.SimpleNamespace` crosses a module boundary. The CLI dispatcher (`_run(args)`) becomes a 3–8 line shim around the typed function.

**Two patterns** — pick per module; **do not** blanket-add `run_<cmd>` wrappers on top of existing typed library functions:

- **Module already has a typed library function** — keep its rich return type, don't shadow with an int-returning wrapper:
  - `wiki/compile.py:211` — `compile_wiki(kb_root, mode, dry_run, source_dirs, max_sources_per_concept, verbose) -> CompileReport`
  - `wiki/lint.py:340` — `lint_wiki(kb_root) -> WikiLintReport`
  - `wiki/maintain.py` — `run_maintenance(kb_root, apply, write_report) -> MaintenanceResult` + `append_query_log(kb_root, query, mode, output_path) -> Path | None`
  - `enrich.py` — `run_enrich_batch(article_dirs, args, concurrency, progress_callback)` (already typed except for `args`; B1 below fixes that)

  Internal callers call the library function directly and inspect `.errors` / equivalent. The CLI `_run(args)` already converts to int — leave that shim alone.

- **Module has no typed library function — extract one**: `sync.py`, `embed.py`, `ingest/source.py`, `query/brainstorm.py`, `agent/cli.py`. Pattern:

  ```python
  def run_<cmd>(kb_root: Path, *, <typed kwargs>) -> int:
      # business logic

  def _run(args: argparse.Namespace) -> int:
      return run_<cmd>(
          resolve_kb_root(getattr(args, "kb_root", None)),
          <kwarg=args.kwarg, ...>,
      )
  ```

### B2. Kill every fake-Namespace site (verified hard list)

Hard acceptance: `grep -rn "argparse.Namespace(\|SimpleNamespace(" quant_llm_wiki/` returns **zero** matches in production code.

1. **`ingest/source.py:309-328`** — replace `SimpleNamespace`-wrapped calls to `wiki.compile._run` and `embed._run` with:
   ```python
   if not no_compile:
       from quant_llm_wiki.wiki.compile import compile_wiki
       from quant_llm_wiki.embed import run_embed
       report = compile_wiki(kb_root, mode="incremental", dry_run=False, verbose=False)
       if report.errors:
           return 1
       rc = run_embed(kb_root, source_dir="reviewed,high-value", force=False, dry_run=False)
       if rc != 0:
           return rc
   ```

2. **`ingest/source.py:40-49` (`_dispatch_wechat`)** — drop the `argparse.Namespace(title=None, content_type=..., dry_run=False, force=...)`. Call `ingest_single_url(url, kb_root=kb_root, title=None, content_type=content_type, dry_run=False, force=force)` with typed kwargs (per B1 wechat refactor).

3. **`agent/tools.py:181-189`** — drop the `argparse.Namespace(...)` block. Call `enrich_discover(articles_root=kb_root / "raw", status_filter=status_filter, limit=limit, article_dir=article_dir)`, `get_concurrency(concurrency=None)`, and `run_enrich_batch(article_dirs, articles_root=kb_root / "raw", force=force, dry_run=False, progress_callback=_progress, concurrency=concurrency)` after the B1 enrich refactor.

### B3. agent/tools.py — thread `kb_root` through every write path

This is the highest-risk change. Today `kb_root = resolve_kb_root(None)` is resolved once at the top of each `@tool` function, but several calls into business code drop it on the floor:

- `ingest_articles` (`agent/tools.py:122-141`):
  - `find_rejected_source(source_url=u)` at `:123` — change to `find_rejected_source(source_url=u, rejected_sources_path=kb_root / "rejected_sources.json")` (per Workstream A2).
  - `ingest_source.dispatch_url(u, content_type=..., force=...)` at `:134` — pass `kb_root=kb_root`.
  - Also the `pdf_file` / `pdf_url` / `html_file` branches not shown above: every `dispatch_*` call must pass `kb_root=kb_root`.
- `set_article_status`: `add_rejected_source(...)` at `:352` — pass `rejected_sources_path=kb_root / "rejected_sources.json"`.
- `enrich_articles`: covered in B2 #3 above.
- Anywhere else in `agent/tools.py` that calls a business function — audit and add `kb_root=kb_root` explicitly.

After this, the dispatchers in `ingest/source.py` should make `kb_root` a **required** kwarg (not `Path | None = None` with a fallback). The only place that falls back to `resolve_kb_root(None)` is the top of each `@tool` function and each module's `_run(args)`.

### B4. Delete legacy `parse_args` in `query/brainstorm.py`

`query/brainstorm.py:69-101` defines a `parse_args()` that builds its own argparse with the same 17 flags as `_add_common_args` (`:104-129`). It's never wired into `qlw cli.py`. Delete it outright (and any `if __name__ == "__main__": main()` block that calls it). Adding `--no-query-log` only to `_add_common_args` would otherwise create a behavior split.

### B5. `__init__.py` re-exports — skipped

`quant_llm_wiki/__init__.py` stays empty. Re-exporting `run_*` would freeze a public API surface that v0.4.0 is still re-shaping; defer to v0.5.0+ if there's ever a downstream consumer.

## Workstream C — Wire `append_query_log` into `ask` / `brainstorm`

**Goal**: Each `qlw ask` / `qlw brainstorm` invocation writes `<kb_root>/wiki/queries/<YYYY-MM-DD>_<slug>_<mode>.md` unless explicitly suppressed. `qlw lint --maintain` already consumes those logs via `run_maintenance()` — no change needed there.

### C1. Add `--no-query-log` flag

In `_add_common_args` (around `query/brainstorm.py:74-96`) add:
```python
parser.add_argument(
    "--no-query-log",
    action="store_true",
    help="Skip writing wiki/queries/<date>_<slug>_<mode>.md after the run.",
)
```

Default behaviour: **log is written**. The flag opts out.

### C2. Call `append_query_log` after `write_output`

In `run_ask` and `run_brainstorm`, after `write_output(...)` (currently `brainstorm.py:189` and `:240`), add:

```python
if write_query_log:
    from quant_llm_wiki.wiki.maintain import append_query_log
    log_path = append_query_log(kb_root, query, command, output_path=saved)
    if log_path:
        print(f"query log: {log_path}")
```

Pass `output_path=saved` explicitly — `append_query_log` already supports it (`maintain.py:115`), and this avoids the `_latest_output_for` glob which would race on a clock-second collision.

In `_run_ask` / `_run_brainstorm` shims, forward `write_query_log=not args.no_query_log`.
